P21.6 — Dire sur le téléphone que l'écran est gardé allumé

Aperçu à valider avant le code (CLAUDE.md). APK de debug seulement. Volet du téléphone tiré vers le bas pendant un test en direct : partage de position en cours, et le PC a lancé cmd.sh awake 30 à 10:42.

Aujourd'hui (0.4.66) = variante A

L'écran reste allumé, le téléphone ne dit pas pourquoi

Seul le PC le sait (événements debug.awake). Pour éteindre : bouton marche (l'écran reste alors éteint) ou cmd.sh awake 0 depuis le PC. Rien à coder.

Tout dans la notification déjà validée (P21.7, variante B). Mais elle appartient à l'appli, pas au module de debug : il faut un crochet dans :app, et le bouton prend une des trois places d'Android (partage + enregistrement + écran : plus de place pour le suivi ou les alertes).

Commande lancée sur le téléphone lui-même (USB, cmd.sh awake 30 here) : « Demandé par adb sur ce téléphone ».

Tout reste dans le module de debug : rien dans l'appli, rien dans l'APK de release, la notification de ToolMap ne change pas. Notification « silencieuse » : pas d'icône de plus dans la barre d'état (l'écran allumé suffit à le voir).

Dans les variantes B et C

  • Elle apparaît au début de la demande, l'heure suit si le PC change la durée, elle part à la fin (heure passée, cmd.sh awake 0 ou le bouton).
  • L'heure est celle du téléphone.
  • « Laisser s'éteindre » rend l'écran à sa mise en veille normale, sans ouvrir ToolMap. Le téléphone ignore ensuite la demande en cours du PC, jusqu'à une nouvelle commande cmd.sh awake. Événement debug.awake on=false why=button, donc le PC le voit.
  • Sans son ni vibration. Toucher la notification ouvre ToolMap.
  • Si les notifications de ToolMap sont refusées, rien ne s'affiche, mais l'écran reste quand même gardé allumé.
